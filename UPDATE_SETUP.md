# Автообновление приложения

Приложение само проверяет новый релиз на GitHub: при запуске (молча) и по кнопке
«Проверить» в Настройки → О приложении → Обновления. Если версия новее — предлагает
скачать, качает APK с полосой прогресса и передаёт его системному установщику.
После установки `UpdateReceiver` перезапускает приложение.

## Что нужно сделать один раз

### 1. Указать репозиторий

В `lib/services/update/update_config.dart`:

```dart
const String kGithubOwner = 'ваш-логин';
const String kGithubRepo = 'vguit_app';
```

Или передать при сборке, не меняя код:

```bash
flutter build apk --release \
  --dart-define=GITHUB_OWNER=ваш-логин \
  --dart-define=GITHUB_REPO=vguit_app
```

Пока стоит `YOUR_GITHUB_LOGIN`, проверка обновлений молча пропускается.

### 2. Подписать APK постоянным ключом

Обновление установится только поверх приложения с **той же подписью**. Сейчас в
`android/app/build.gradle.kts` релиз подписан debug-ключом — этого хватит, только
если вы всегда собираете на этой же машине и не потеряете `~/.android/debug.keystore`.

Правильный вариант — создать свой keystore **до первого публичного релиза**:

```bash
keytool -genkey -v -keystore vguit-release.jks -keyalg RSA \
  -keysize 2048 -validity 10000 -alias vguit
```

`key.properties` и `.jks` в репозиторий не коммитить. Сменить ключ после того,
как люди установили APK, нельзя — обновления перестанут ставиться.

### 3. Поднять версию и собрать

```bash
# pubspec.yaml: version: 1.1.0+2   (build number обязательно увеличивать)
flutter build apk --release
```

Файл: `build/app/outputs/flutter-apk/app-release.apk`.

### 4. Опубликовать релиз

Тег — версия с `v`, к релизу приложить APK (имя любое, важно расширение `.apk`):

```bash
git tag v1.1.0
git push origin v1.1.0
gh release create v1.1.0 build/app/outputs/flutter-apk/app-release.apk \
  --title "1.1.0" --notes "Что нового: ..."
```

Или через веб: Releases → Draft a new release → Tag `v1.1.0` → прикрепить APK →
Publish. Приложение читает `GET /repos/{owner}/{repo}/releases/latest` и берёт
первый asset с расширением `.apk`.

## Как это работает внутри

| Шаг | Где |
|---|---|
| Запрос последнего релиза | `UpdateService.check()` → GitHub API |
| Сравнение версий | `isNewerVersion()` — числовое, 1.0.10 > 1.0.9 |
| Скачивание с прогрессом | `UpdateService.download()` → кэш `cache/updates/` |
| Установка | `MainActivity` → `FileProvider` + `ACTION_VIEW` (package-archive) |
| Перезапуск | `UpdateReceiver` на `MY_PACKAGE_REPLACED` |

## Ограничения, которые нельзя обойти

1. **Полностью тихой установки нет.** Android показывает своё окно «Установить?» —
   его нельзя пропустить без root или прав device-owner. Зато не нужно искать файл
   в проводнике: он уже в кэше приложения.
2. **Один раз нужно разрешить установку** из этого приложения (Android 8+):
   приложение открывает нужный экран настроек само.
3. **Фоновой проверки нет** — только при запуске и по кнопке.
4. **Перезапуск после установки** может не сработать на Android 10+: система
   ограничивает запуск активности из фона. Тогда приложение просто откроется
   вручную, ничего не сломается.
5. Обновления только для Android; на других платформах раздел показывает пояснение.

## Отладка

- «Проверить» в настройках показывает реальные ошибки: нет сети, нет релизов (404),
  в релизе нет APK, GitHub ограничил запросы (403).
- Не скачивается? Проверьте, что asset прикреплён к релизу, а не лежит в исходниках.
- «Приложение не установлено» при установке — почти всегда разные подписи
  у установленной и новой версии.
