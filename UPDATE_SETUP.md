# Обновления приложения

Приложение проверяет последний релиз на GitHub: при запуске (молча) и по кнопке
«Проверить» в Настройки → О приложении → Обновления. Если версия новее, показывает
окно с описанием изменений, а кнопка «Скачать» открывает APK в браузере.
Установку выполняет система — приложение не запрашивает разрешение
`REQUEST_INSTALL_PACKAGES`, поэтому Google Play Protect не показывает
предупреждение «может устанавливать другие приложения».

> **История.** В версиях 1.0.0 и 1.0.1 приложение скачивало APK само и передавало
> его системному установщику через FileProvider. Из-за разрешения
> `REQUEST_INSTALL_PACKAGES` Play Protect предупреждал пользователей. Начиная
> с 1.0.2 механизм заменён на ручное скачивание через браузер.

## Что нужно сделать один раз

### 1. Указать репозиторий

В `lib/services/update/update_config.dart`:

```dart
const String kGithubOwner = 'ваш-логин';
const String kGithubRepo = 'vguit_app';
```

Или передать при сборке, не меняя код:

```bash
flutter build apk --release \
  --dart-define=GITHUB_OWNER=ваш-логин \
  --dart-define=GITHUB_REPO=vguit_app
```

Пока стоит `YOUR_GITHUB_LOGIN`, проверка обновлений молча пропускается.

### 2. Подписать APK постоянным ключом

Обновление установится только поверх приложения с **той же подписью**.
Параметры хранятся в `android/key.properties` (в git не попадает):

```properties
storeFile=../vguit-release.jks
storePassword=…
keyAlias=…
keyPassword=…
```

Без этого файла debug-сборки работают как обычно, а `--release` падает
с понятным сообщением — чтобы случайно не опубликовать APK на debug-ключе.

### 3. Поднять версию и собрать

```bash
# pubspec.yaml: version: 1.0.2+3   (build number обязательно увеличивать)
flutter build apk --release
```

Файл: `build/app/outputs/flutter-apk/app-release.apk`.

### 4. Опубликовать релиз

Тег — версия с `v`, к релизу приложить APK (имя любое, важно расширение `.apk`):

```bash
git tag v1.0.2
git push origin v1.0.2
gh release create v1.0.2 build/app/outputs/flutter-apk/app-release.apk \
  --title "1.0.2" --notes "Что нового: ..."
```

Или через веб: Releases → Draft a new release → Tag `v1.0.2` → прикрепить APK →
Publish. Приложение читает `GET /repos/{owner}/{repo}/releases/latest` и берёт
первый asset с расширением `.apk`.

## Как это работает внутри

| Шаг | Где |
|---|---|
| Запрос последнего релиза | `UpdateService.check()` → GitHub API |
| Сравнение версий | `isNewerVersion()` — числовое, 1.0.10 > 1.0.9 |
| Показ окна с изменениями | `UpdateFlow._offer()` |
| Открытие ссылки на APK | `MainActivity.openUrl` → системный браузер |
| Установка | системный установщик Android |
| Текущая версия | `MainActivity.appInfo` (из манифеста) |

## Ограничения, которые нельзя обойти

1. **Установку подтверждает система.** Диалог «Установить?» пропустить нельзя
   без root или прав device-owner — это ограничение Android, а не приложения.
2. **Два лишних шага у пользователя:** скачать файл в браузере и открыть его
   из «Загрузок» (или из уведомления браузера).
3. **Фоновой проверки нет** — только при запуске и по кнопке.
4. Обновления только для Android; на других платформах раздел показывает пояснение.

## Отладка

- «Проверить» в настройках показывает реальные ошибки: нет сети, нет релизов (404),
  в релизе нет APK, GitHub ограничил запросы (403).
- Не скачивается? Проверьте, что asset прикреплён к релизу, а не лежит в исходниках.
- «Приложение не установлено» при установке — почти всегда разные подписи
  у установленной и новой версии.
- Проверить, что в APK нет лишнего разрешения:

  ```bash
  aapt2 dump permissions app-release.apk | findstr INSTALL_PACKAGES
  ```

  Пусто — значит Play Protect не должен предупреждать об установке приложений.
